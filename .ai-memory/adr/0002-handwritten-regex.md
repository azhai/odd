# ADR 0002 — 自研正则引擎（Odin 没有 core:regex）

- 状态：已采纳
- 日期：2026-10-24

## 背景

gx 的 find / replace / rename / script 全靠 Go 的 `regexp`（RE2）。odd 要在
Odin 里复刻行为，但 **Odin dev-2026-10 的 core 与 vendor 都没有正则包**。

可选路径：

1. 绑定 PCRE2 / Oniguruma（C 库）——需要 vendored 静态库 + 平台差异
2. 移植一个小型正则实现
3. 自己实现常用子集

## 决策

自己实现：`search/regex.odin`，三段式。

- **解析器**：递归下降 → AST。支持分组 `(...)`、命名组 `(?P<n>...)` / `(?<n>...)`、
  非捕获组 `(?:...)`、字符类（含范围、取反、转义 `\d\w\s` 等）、量词
  `* + ? {n,m}`（含惰性 `?`）、锚点 `^ $ \b`、反向引用 `\1`、交替 `|`、
  以及 `regex_quote_meta`（给 `-F` 字面模式用）。
- **编译**：AST → 字节码，左优先序（与 Go regexp 默认一致）。
- **执行**：回溯 VM，每步计数，超过上限即失败（防灾难性回溯）。

**字面量模式走子串搜索快路径**：`regex_has_meta` 判定无元字符时直接
`strings.index`，不启动 VM。

**模板展开单独实现**（`expand_template` + `extract_group_ref`），逐字复刻
Go 的 `Expand` 语义：`$` 后取最长 `[A-Za-z0-9_]+`、全数字才当组号、禁止前导
零（`$01` 当名字查）、越界/查不到产出空串、**没有单数字回退**、`${` 缺 `}`
时 `$` 原样输出。

## 后果

- 好的：零外部依赖，跨平台一致，构建不需要 C 库。
- 好的：模板语义与 Go 完全对齐——`rename '(foo)_(one)' '$2_$1'` 这种
  用例能逐字节匹配（早期版本在这里错过，见 `.ai-memory/progress.md`）。
- 代价：只覆盖 RE2 的常用子集。不支持的语法（如 `\p{L}`、lookahead）
  会编译失败而不是静默错配。
- 代价：非法正则的错误文本不含 Go 解析器的原文细节，差分矩阵对这一行做
  归一化（`README.md` 的已知偏差表有记录）。
- 代价：回溯 VM 在病态模式上仍然比 RE2 慢，因此必须有步数上限。
