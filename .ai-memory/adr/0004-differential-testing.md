# ADR 0004 — 用差分测试作为验收主线

- 状态：已采纳
- 日期：2026-10-24

## 背景

"复刻 gx"这个目标有个特殊性质：**正确答案已经存在于另一个程序里**。
这既降低了难度（不用设计行为），也提高了要求（不能"差不多"）。

`odin test` 只能验函数级行为。它验不了的东西恰好是复刻里最容易出错的部分：

- 进程级 stdout/stderr 的**逐字节**文本（空格、ANSI 色码、结尾换行）
- 退出码（0/1/2 的三态语义）
- 多个文件被写盘后的最终内容

而且 Odin 的测试运行器并行跑用例，捕获进程 stdout 会互相污染——在单测里
断言输出文本这条路本身就不通。

## 决策

三层验收，从廉价到昂贵：

1. `tools/guard.sh` —— 静态护栏（依赖方向 / os.exit 位置 / panic / odin check），
   秒级，先跑
2. `./test.sh` —— `odin test` 逐包，覆盖函数级逻辑 + 内存泄漏
3. `./tests/run.sh` —— **差分矩阵**：同一条命令分别喂给 `gx` 与 `odd`，
   比对 stdout / stderr / 退出码 / 工作树（文件名集合 + 内容哈希）

比对用落盘 + `cmp`，不用 `$( )` 捕获——命令替换会吃掉结尾换行，
"有没有换行"这种差异就漏了。

归一化只做六件事（其余逐字节）：私有工作目录路径 → `<D>`、程序名 `gx` → `odd`、
版本串 → `<VER>`、非法正则细节 → `<PAT>`、Tengo → 空。每一项都在
`README.md` 的已知偏差表里有原因。

`./verify.sh` 串起三层；拿不到 gx 二进制时跳过第三层并返回 0
（odd 可以独立开发，不该因为参照物缺席就判红）。

## 后果

- 好的：抓到了单测永远抓不到的 bug。典型例子：`-F` 固定串因 `defer` 块作用域
  提前释放而全部失效（输出为空），单测里"函数返回了什么"看不出来。
- 好的：修改后行为漂移会立刻定位到具体命令和具体字符。
- 代价：需要 gx 二进制存在（`GX=` 可指向任意位置）。
- 代价：夹具成本。本机 `touch`/`SetFile` 被沙箱 shim 包装成 IPC 调用，
  每次建树几十次调用 → 分钟级甚至挂起。所以只读命令的夹具只建一次，
  会写盘的命令用「母版 + `cp -a` 克隆」。这条经验写在 AGENTS.md 里。
- 代价：矩阵 172 条要跑约 1.5 分钟，不适合放进每次保存的循环；
  用 `--quick` 或 `FILTER=` 缩小范围。
