# ADR 0005 — 遍历与输出顺序确定化

- 状态：已采纳
- 日期：2026-10-24

## 背景

gx 的 walker 把遍历结果送进 channel，多个 worker 并发处理，输出顺序**不稳定**
（同一目录跑两次，行的先后可能不同）。它是给终端用户看的工具，这不影响使用。

但对 odd 来说，这直接影响可测性：差分矩阵要逐字节比对 stdout，参照物的顺序
不定就等于基线不定。

## 决策

遍历顺序确定化：

- 每层目录按名字排序（`os.read_directory_by_path` 后排序），等价于 Go
  `WalkDir` 的词法序
- find / replace 的 `-j N` 仍然真并行处理文件，但**结果按文件序输出**
  （worker 只算命中的行，输出由一个有序的收集环节落盘）
- list 的 `-s` 排序本身就是显式的，不受影响

`-j` 的语义与 gx 保持一致（包括两个怪癖）：find 搜索模式 `-j 0` = 全部核心；
replace 的 `-j 0` = 零个 worker，什么都不做（gx 原样，差分用例
`dry -j 0 零 worker` 覆盖）。

## 后果

- 好的：差分矩阵比对稳定，flaky 用例为零。
- 好的：用户看到的顺序可预期（同一目录两次输出一致）。
- 代价：并行度只体现在"文件级"，单文件内部仍是串行；对超大单文件没有加速。
- 代价：为了有序输出，worker 的结果要先攒着再按序写，内存占用比"谁先算完谁
  先写"略高（每个待输出文件最多攒一个文件的结果）。
- 已知偏差：gx 那边顺序不定，因此差分矩阵在顺序上比的是"同一个顺序"——
  如果某个用例 gx 恰好输出顺序不同，会被判 FAIL。目前 172 条未出现。
